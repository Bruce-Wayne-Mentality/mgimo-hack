# Личное расписание учебного офиса

Python-парсер расписания ВШЭ и HTTP API для сайта вымышленного вуза. Механизм: подтверждённый аккаунт → email → карточка студента → его занятия. Результат можно показывать в личном кабинете учебного офиса.

Реализованы загрузка и нормализация занятий, справочник персональных назначений, API, уведомления и демонстрационный личный кабинет с колокольчиком. Интерфейс вашего сайта подключается к тому же API.

## Быстрый запуск

Нужен Python 3.11+. Выполняйте команды из корня репозитория:

```bash
python -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python -m hse_schedule serve --demo
```

Откройте [демонстрационный кабинет](http://127.0.0.1:8000/): в нём можно выбрать Алису или Бориса, посмотреть пары, настройки и колокольчик. Документация API — `/docs`, проверка запуска — `/health`. Страница кабинета доступна только в режиме `--demo`.

Демонстрационные аккаунты:

| Студент | Email | Bearer-токен |
| --- | --- | --- |
| Алиса | `alice@demo-university.test` | `demo-alice-token` |
| Борис | `bob@demo-university.test` | `demo-bob-token` |

```bash
curl 'http://127.0.0.1:8000/api/me/schedule?start=2026-11-09&finish=2026-11-15' \
  -H 'Authorization: Bearer demo-alice-token'
```

Поменяйте токен на `demo-bob-token`: общие лекции сохранятся, семинары изменятся. За полную учебную неделю у каждого студента по четыре занятия: две общие лекции и два собственных семинара. Кабинет открывает неделю с понедельника по воскресенье; соседние недели можно переключать кнопками.

Данные в `examples/lessons.json` синтетические: это шаблон недели 9–15 ноября 2026 года. В режиме `serve --demo` он повторяется по дням недели для запрошенного периода, поэтому демо не пустеет после смены даты. Идентификаторы занятий учитывают дату и остаются стабильными после перезапуска. У Алисы по пятницам занятий нет; запрос только на пятницу корректно вернёт пустой список, а полная неделя покажет все четыре занятия.

Команды `parse`, `fetch`, `schedule --fixture` и запуск без `--demo` сохраняют исходные даты. Настоящее расписание ВШЭ автоматически не повторяется и не переносится.

## Уведомления и колокольчик

У каждого аккаунта свой общий переключатель уведомлений; по умолчанию он выключен.

- За 10 минут до пары создаётся напоминание.
- При добавлении, отмене или изменении пары создаётся сообщение с прежними и новыми данными.
- Все события сохраняются в колокольчике. Когда уведомления включены, они также отправляются в подключённые браузеры и привязанный Telegram; когда выключены — остаются только в колокольчике.

В колокольчике есть счётчик непрочитанных, отметка отдельного сообщения и действие «Прочитать всё». Повторное включение уведомлений не рассылает старые события из колокольчика. Настройки, история, прочтение, подписки и очередь доставок переживают перезапуск: SQLite находится в `.local-state/demo/notifications.sqlite3` или `.local-state/live/notifications.sqlite3`. Каталог можно изменить через `--state-dir`; локальное состояние исключено из Git.

Сервер сам проверяет расписание на ближайшие семь дней каждые 60 секунд (`--refresh-interval`). Напоминания проверяются отдельно каждые 5 секунд: возможна задержка до следующей проверки и доставки провайдером. Первый успешный снимок создаёт исходное состояние без массовых сообщений «пара добавлена». Ошибка источника сохраняет предыдущий снимок и не превращает занятия в отменённые. Повторные проверки и перезапуск не создают повторных событий; просроченные напоминания не отправляются.

### Браузерные push-уведомления

В кабинете нажмите «Включить в браузере» и разрешите уведомления. Это подключит браузер и включит общий переключатель. Нужны HTTPS либо `localhost` и поддержка Web Push; обычный HTTP по удалённому IP не подходит. Доставка идёт через service worker, поэтому открытая вкладка не обязательна; её доступность также зависит от браузера и настроек устройства.

VAPID-ключ автоматически создаётся в `.local-state/{demo,live}/vapid-private.pem`. Сохраняйте этот ключ вместе с резервной копией SQLite: при его замене браузеры потребуется подключить заново. Для своего сервера укажите контакт владельца через `--push-contact mailto:admin@your-university.example`. Недействительные подписки удаляются; при временном сбое отправка повторяется, а событие остаётся в колокольчике.

### Telegram от имени бота

Создайте бота через [BotFather](https://t.me/BotFather) и задайте его токен на сервере в `TELEGRAM_BOT_TOKEN`. Например, в Bash можно ввести его без отображения и сохранения в команде:

```bash
read -rs -p 'Токен Telegram-бота: ' TELEGRAM_BOT_TOKEN
export TELEGRAM_BOT_TOKEN
.venv/bin/python -m hse_schedule serve --demo
```

Имя бот получит через `getMe`; при необходимости задайте `TELEGRAM_BOT_USERNAME` без `@`. Не добавляйте реальные токены в репозиторий. Без токена кабинет работает, но создание ссылки привязки возвращает `503`.

В своём кабинете нажмите «Привязать Telegram», откройте полученную ссылку и нажмите «Запустить» в личном чате бота. Одноразовая ссылка действует 10 минут и связывает чат с текущим авторизованным аккаунтом; произвольный Telegram username не используется для назначения получателя. Привязка сама не включает уведомления: общий переключатель должен быть включён. Кнопка «Отвязать аккаунт» прекращает доставку в этот чат.

Бот опрашивает `getUpdates` каждые 3 секунды. Запускайте один процесс опроса для одного токена; если у бота уже есть webhook, его должен предварительно отключить владелец. Приложение не удаляет существующий webhook автоматически.

### Проверка изменений без обращения к ВШЭ

Файловый источник перечитывает выгрузку при запросах. Для эксперимента через API создайте копию, сохранив исходные примеры:

```bash
cp examples/lessons.json lessons.local.json
```

В `tokens.local.json` задайте `{"demo-alice-token":"alice@demo-university.test"}`, затем запустите:

```bash
.venv/bin/python -m hse_schedule serve --students examples/students.json \
  --fixture lessons.local.json --tokens-file tokens.local.json \
  --refresh-interval 5 --state-dir .local-state/check
```

После первой проверки измените аудиторию будущей пары в копии. В течение следующей проверки событие появится в `GET /api/me/notifications`; включённые каналы также получат его. Даты пары должны попадать в ближайшие семь дней. Для проверки напоминания задайте начало примерно через 10 минут. Этот запуск предоставляет API; страница демокабинета включается только флагом `--demo`.

## Откуда берутся пары

Загрузчик использует JSON публичного портала ВШЭ: [www.hse.ru/api/timetable/lessons](https://www.hse.ru/api/timetable/lessons). Его параметры подтверждены кодом [страницы расписания](https://www.hse.ru/ba/ami/timetable):

```text
groupoid=88229
receiverType=3
fromdate=2026.11.09
todate=2026.11.15
```

Ответ содержит `Lessons` и `StatusCode`. Поддерживается также массив занятий. Парсер возвращает название, тип занятия, начало и конец с часовым поясом, преподавателей, учебные группы, подгруппу, аудиторию, корпус и ссылки. Точные дубликаты удаляются; разные даты и варианты занятий сохраняются.

При проверке запрос группы `88229` за 9–15 ноября 2026 года вернул 48 исходных занятий. Повторные запросы из облачной среды также получали `502`: доступ к живому порталу нестабилен. Для демонстрации на хакатоне используйте автономный режим; он не зависит от доступности ВШЭ.

Сервис [ruz.hse.ru](https://ruz.hse.ru/) доступен из внутренней сети ВШЭ — это указано на [официальной странице доступа](https://www.hse.ru/eduland/schedule/). При внешнем запросе он может перенаправить на HTML-страницу. Загрузчик считает редирект или HTML ошибкой доступа, а не отсутствием пар.

Получить группы выбранной образовательной программы и загрузить её расписание:

```bash
.venv/bin/python -m hse_schedule groups \
  --url https://www.hse.ru/ba/ami/timetable

.venv/bin/python -m hse_schedule fetch --group 88229 \
  --start 2026-11-09 --finish 2026-11-15 --output /tmp/hse-lessons.json
```

Разобрать ранее сохранённый **исходный** JSON ВШЭ без сети:

```bash
.venv/bin/python -m hse_schedule parse \
  --input examples/lessons.json --output /tmp/normalized-lessons.json
```

`fetch`, `parse` и `schedule` выводят нормализованные занятия; это выходной формат для сайта, он отличается от исходного JSON ВШЭ.

## Как определяется личное расписание

Почта связывается с учебным планом в собственном справочнике учебного офиса. По одной произвольной почте публичный источник ВШЭ не позволяет достоверно определить занятия.

`examples/students.json` показывает вариант с явными назначениями на учебные группы:

```json
{
  "students": [
    {
      "email": "alice@demo-university.test",
      "name": "Алиса Демо",
      "group_oids": ["1000", "1001"]
    }
  ]
}
```

Здесь `1000` — общая лекционная группа, `1001` — семинарская группа Алисы. Email нормализуется: убираются пробелы по краям, регистр не учитывается. Повторяющиеся аккаунты и пустые назначения отклоняются.

В режиме `group_oids` сервис дополнительно проверяет принадлежность каждого занятия назначенным учебным группам. Занятия других групп и записи без сведений о группе в личное расписание не попадают.

Для источника с индивидуальным расписанием вместо `group_oids` можно указать `student_oid`. Адаптер передаст `studentoid` и `receiverType=0`; ID должен поступать из авторизованного справочника. Живой индивидуальный запрос не проверен, его доступность зависит от политики источника. Файловая демонстрация поддерживает только назначения на группы.

**Академическая группа и персональный учебный план могут различаться.** Ответ по академической группе ВШЭ может включать альтернативные языковые группы, майноры и другие варианты. Для точного ЛК нужны индивидуальный ID либо проверенные назначения на конкретные учебные группы. Эти назначения задаёт учебный офис; приложение не выводит их из email.

Проверить связку без HTTP:

```bash
.venv/bin/python -m hse_schedule schedule \
  --students examples/students.json --fixture examples/lessons.json \
  --email alice@demo-university.test \
  --start 2026-11-09 --finish 2026-11-15
```

Без `--fixture` команда использует живой источник ВШЭ; для него подставьте действительные назначения в собственном справочнике.

## Подключение к сайту

| Метод и путь | Назначение |
| --- | --- |
| `GET /health` | Доступность приложения и признак деморежима |
| `GET /api/me` | Email и имя текущего студента |
| `GET /api/me/schedule?start=YYYY-MM-DD&finish=YYYY-MM-DD` | Личное расписание текущего студента |
| `GET /api/me/notifications` | Колокольчик: `limit`, `before`, `unread_only`; ответ содержит `items`, `unread_count`, `next_before` |
| `POST /api/me/notifications/{id}/read` | Отметить своё уведомление прочитанным |
| `POST /api/me/notifications/read-all` | Прочитать все свои уведомления |
| `GET`, `PATCH /api/me/notification-settings` | Получить или изменить `{"enabled":true}` |
| `GET /api/push/public-key` | Публичный VAPID-ключ для браузера |
| `POST`, `DELETE /api/me/push-subscriptions` | Подключить подписку браузера или удалить её по `endpoint` |
| `GET /api/me/telegram` | Статус привязки Telegram |
| `POST /api/me/telegram/link` | Одноразовые `deep_link` и `expires_at` |
| `DELETE /api/me/telegram` | Отвязать Telegram и отменить ожидающие доставки |

Защищённые методы принимают `Authorization: Bearer <токен>`. Email определяется на сервере по токену; параметр `email` в запросе не переключает аккаунт. Ответ расписания содержит `student`, `start`, `finish`, `timezone`, `lessons` и `demo`. По умолчанию используется `Europe/Moscow`; время занятий возвращается в ISO 8601 с часовым смещением.

Для запуска с собственными данными создайте `students.local.json` и закрытый `tokens.local.json` формата:

```json
{
  "example-server-issued-token": "student@university.test"
}
```

```bash
.venv/bin/python -m hse_schedule serve \
  --students students.local.json --tokens-file tokens.local.json
```

В реальном сайте выдачу токенов после проверки аккаунта обеспечивает ваша система авторизации; этот backend проверяет заданное сопоставление. Приведённый токен — только пример. Файлы `*.local.json` исключены из Git. Реальные токены и данные студентов храните отдельно от публичных примеров. Для локального источника дополнительно передайте `--fixture путь/к/исходным-занятиям.json`.

В существующем приложении создайте `ScheduleService(directory, source)` и `create_app(service, tokens={})`, затем подключите свою проверенную сессию/JWT вместо встроенного сопоставления токенов:

```python
from hse_schedule.api import create_app

app = create_app(service, tokens={})
app.dependency_overrides[app.state.account_dependency] = get_verified_account_email
```

`get_verified_account_email` — функция авторизации вашего сайта: она проверяет сессию и возвращает email аккаунта либо отклоняет запрос. Email из формы или query-параметра не является подтверждением личности. Frontend запрашивает `/api/me/schedule` через общий домен сайта; JSON можно сразу использовать для календаря или списка пар.

Для уведомлений при создании приложения дополнительно передайте `notification_store=NotificationStore(path)`, `push_sender=WebPushSender(key_path, contact)` и, при наличии бота, `telegram_bot=TelegramBot(token)`. Фоновые проверки включаются через `run_workers=True`. CLI `serve` уже создаёт эти компоненты и запускает проверки. Браузер регистрирует `/sw.js`, получает публичный ключ, сохраняет свою подписку через API и запрашивает разрешение пользователя; для собственного frontend подключите аналогичный service worker. Встроенный `/sw.js` раздаётся вместе с демонстрационной страницей.

Период включает обе даты и ограничен 31 днём. Неверный период даёт `422`, отсутствие авторизации — `401`, отсутствие студента в справочнике — `404`. Ошибка источника даёт `502`; корректное отсутствие занятий — `200` с `lessons: []`. Для персональных ответов установлен `Cache-Control: private, no-store`.

## Проверка и расширение

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Тесты не требуют доступа к ВШЭ. Проверяются разбор данных, персональные назначения, разделение аккаунтов, напоминания, изменения расписания, колокольчик, привязка Telegram и повторные доставки. Web Push и Telegram проверяются с подменёнными HTTP-транспортами; это не подтверждает получение сообщения реальным устройством. CI запускает тесты на Python 3.11 и 3.12.

Справочник сейчас файловый; его можно заменить данными учебного офиса из БД. Любой источник с методом `schedule(start=..., finish=..., student_oid=... / group_oid=...)` можно подключить к `ScheduleService`. Фоновый мониторинг сохраняет последние успешные снимки расписания в SQLite; это состояние для сравнения и напоминаний, а не редактор учебного плана.
