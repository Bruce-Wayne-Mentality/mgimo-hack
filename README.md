# Цифровой деканат · концепт для конкурса

**Личный кабинет студента, в котором деканат пишет первым, а не ждёт студента в очереди.**

🔗 **Прототип:** <https://144-31-68-255.sslip.io> — открывается с телефона, без VPN.
Вуз, люди, оценки, документы и правила — вымышлены. Это не официальный сервис какого-либо вуза; логотип — собственный знак проекта.

## Демо за 7 минут

1. **Вход → «Как у меня дела».** Войдите как Вера. Главный экран сразу отвечает на главный вопрос: «В графике по 2 из 6 дисциплин» и карточки «Деканат пишет первым» — что не так и что делать.
2. **Светофор с объяснением.** «Учёба» → «Математический анализ»: шкала баллов с отметкой «должно быть к сегодня», причины словами, кнопка «Подать заявку на пересдачу», «Что если» с ползунками, история изменений, «Как это считается».
3. **Ассистент.** «Ещё → Ассистент»: «Как у меня дела?», «Какие пары завтра?», «Нужна справка в банк» (готовит черновик — студент подтверждает), «Покажи оценки Бориса» (отказ: только свои данные), «Позвать сотрудника» (вопрос уходит в очередь деканата).
4. **Справка за минуту.** Войдите как Анна → «Заявки» → готовая справка → «Открыть PDF». Наведите камеру телефона на QR в PDF — откроется публичная проверка подлинности; туда же можно перетащить файл, и браузер сверит SHA-256.
5. **Деканат.** Войдите как сотрудник: панель факультета («Кому стоит написать первыми», просрочки по SLA), «Журнал» → поставьте балл Борису — светофор пересчитается, студент получит уведомление; «Объявления» → опубликуйте группе.
6. **Расписание и бронь.** Анна: на главной у сегодняшней пары плашка «Перенесена: было …» с причиной. «Ещё → Бронирование» — выберите слот в коворкинге; занятое время зачёркнуто, пары в аудиториях подсвечены. Сотрудник: «Ещё → Расписание групп» — перенесите или отмените пару, студенты получат уведомление.
7. **Студенческий и «Красная кнопка».** Студент: «Ещё → Студенческий» — QR меняется каждые 60 секунд. «Красная кнопка» → анонимное обращение → одноразовый код. Администратор видит его в очереди с SLA и отвечает с обязательной мотивировкой.

## Безопасность простыми словами

- Пароли — только argon2id-хэши; проверка пароля вынесена из цикла событий, чтобы вход не тормозил остальных.
- Сессия — в куке `__Host-session` (HttpOnly, Secure, SameSite=Lax); в базе только SHA-256 токена. Каждое изменение требует CSRF-токен.
- Студент видит только своё: чужая заявка, оценка, документ или обращение отвечают «не найдено» — это проверяют автотесты (IDOR).
- Сотрудник видит только свой факультет и типы заявок из своих полномочий; просмотр журнала оценок пишется в аудит.
- Публичные ссылки подписаны HMAC (справка, студенческий) или хранятся как отпечаток (календарь, код обращения). Подделка и отсутствие документа выглядят одинаково.
- Анонимное обращение не хранит автора — это ограничение в самой БД (`CHECK`); IP не пишется.
- Лимиты запросов: вход, публичные проверки, ассистент, общий потолок на API. Строгий CSP, `X-Frame-Options: DENY`, HSTS на прокси.
- Секреты — только в переменных окружения сервера, ключей в коде и браузере нет.

## Архитектура

- **Бэкенд:** Python 3.12, FastAPI, SQLAlchemy 2 (async), Alembic, PostgreSQL 16. Модули: `accounts`, `student_requests`, `academics`, `documents`, `assistant`, `announcements`, `calendar_feed`, `complaints`, `student_id`, `booking`, `schedule_changes`, `admin`.
- **Фронтенд:** React 19, TypeScript, Vite, Tailwind 4, TanStack Query, React Router; дизайн-система «Soft Blue» (`obsidian/04 — Дизайн`). Mobile-first от 360 px.
- **Сервер:** VPS, systemd, Caddy (HTTPS Let's Encrypt, HSTS), PostgreSQL локально. В режиме `--demo` миграции и демо-данные применяются при старте.
