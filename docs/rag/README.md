# RAG для ассистента K4: как собрать, включить и проверить

Ассистент отвечает на вопросы о правилах вуза по документам базы знаний: находит фрагменты гибридным поиском (BM25 + векторы GigaChat, слияние RRF), формулирует ответ только по ним, сервер сам проверяет источники и каждое число. Вопрос без ответа в правилах не выдумывается: «В правилах ответа нет» + кнопка «Спросить деканат», а вопрос (без имени и контактов) попадает сотруднику в «Пробелы базы». Ответ сотрудника становится новым фрагментом базы.

Документы — вымышленный университет «НИУ СТ» (`rag_test_data/`), это концепт для конкурса, а не правила реального вуза.

## Как собрать базу

```bash
pip install -e ".[kb]"                                            # pdfplumber и beautifulsoup4 — только для сборки
python tools/rag_dataset/generate.py                              # (необязательно) пересоздать 11 PDF и 3 HTML
python tools/rag_dataset/verify.py                                # проверить стенд
python -m hse_schedule.cli kb-build --manifest rag_test_data/manifest.json
python -m hse_schedule.cli kb-embed                               # векторы через GigaChat; без ключа — пропуск
python -m hse_schedule.cli kb-stats
```

База берётся из `DATABASE_URL` (или `--database-url`), без них — SQLite демо-режима в `.local-state/demo/app.sqlite3`. `kb-build` перенарезает только изменившиеся файлы (sha256 файла + версия правил нарезки); `kb-embed` считает векторы только для фрагментов без вектора или с другой моделью и сохраняет каждый батч.

В демо-режиме (`serve --demo`) при `RAG_ENABLED=true` база собирается сама при старте. Сброс демо-данных базу знаний не трогает — очищаются только «Пробелы базы» и опубликованные ответы сотрудников.

## Как включить

В окружении сервера: `RAG_ENABLED=true`. Выключено (по умолчанию) — ассистент отвечает по 15 встроенным правилам, как раньше. Пустая база при включённом флажке — тоже 15 правил (резерв).

Не меняется ни при каком значении флажка: защита от инъекций и чужих данных, черновики заявок («сделай за меня»), ответы «про меня» (баллы, пары, заявки, дедлайны). Ответы «про меня» никогда не уходят в GigaChat.

## Без оплаченных эмбеддингов

На Freemium бесплатны только чат-модели, поэтому без векторов работают две доработки:

- **переписывание запроса**: чат-модель перечисляет термины положений для замаскированного вопроса, BM25 ищет и по ним (режим `bm25_rewrite`, свои пороги в `thresholds.json`); при недоступном GigaChat поиск идёт по одному вопросу;
- **модель ответа** задаётся отдельно: `GIGACHAT_ANSWER_MODEL=GigaChat-2-Pro` — по замеру лучшая из Lite, Pro и Max (36 из 36 верных ответов за три прогона, [EVAL.md](EVAL.md)). «Красная кнопка» остаётся на `GIGACHAT_MODEL`.

Сравнить модели на своём ключе: `python -m hse_schedule.cli kb-eval --answers GigaChat-2,GigaChat-2-Pro,GigaChat-2-Max --database-url sqlite:///tmp/eval.sqlite3` (отдельная база — чтобы отказы не попали в очередь пробелов).

## Как проверить качество

```bash
python -m hse_schedule.cli kb-eval --questions rag_test_data/questions.json            # метрики и разбор промахов
python -m hse_schedule.cli kb-eval --questions rag_test_data/questions.json --calibrate  # записать пороги
```

Результаты и ограничения — в [EVAL.md](EVAL.md). Регрессия — `tests/test_kb_eval.py`.

## Что работает без GigaChat

| Нет ключа, недоступен, 402, размыкатель открыт | Поведение |
| --- | --- |
| Эмбеддинги | поиск в режиме `bm25_only`, без обращений к GigaChat, пока в базе нет векторов |
| Генерация ответа | точная цитата лучшего фрагмента с подписью «Из документа …, пункт …» и пунктом, на который он ссылается |
| Отказ и очередь пробелов | работают одинаково |

Исключения GigaChat наружу не выходят. В лог пишутся только вид ответа, режим, время и id фрагментов.

## Что уходит в GigaChat

Только системный промпт, замаскированный вопрос (e-mail, телефоны, ФИО, длинные номера заменены) и до 5 фрагментов правил в тегах `<source>`. Никогда — профиль, оценки, заявки, расписание, id пользователя, ФИО.

## Известные ограничения

- **Эмбеддинги по ключу проекта не оплачены (HTTP 402)**: в бесплатный пакет Freemium входят только чат-модели. Поиск — BM25 с переписыванием запроса, векторные метрики «не измерены» ([NOTES.md](NOTES.md)). После покупки пакета эмбеддингов: `kb-embed`, затем `kb-eval --calibrate`.
- Пороги отказа подобраны на 15 синтетических вопросах — ориентир, а не гарантия; на реальных документах их нужно перекалибровать.
- Синонимы («нейросети» ↔ «ИИ-инструменты») без векторов ловятся плохо; часть таких вопросов спасает раскрытие перекрёстных ссылок.
- Аудитория документов (иностранцы, бакалавры, магистры) хранится, но не фильтрует поиск: в профиле демо-студента нет гражданства.
- Сканы без текстового слоя не разбираются — `kb-build` останавливается с именем файла.
