## Реализация по спецификации (2026-11-17)

Модуль переписан по спецификации «Красная кнопка — спецификация модуля обращений» (9 ноября): `hse_schedule/redbutton`, миграция 0007, экраны К1–К5 и А1–А3.

- **Этап 1 (CPU):** нормализация с гомоглифами и разнесёнными буквами, словарь корней мата с allowlist и подсветкой, `cointegrated/rubert-tiny-toxicity` (ONNX int8, MIT, ~12 МБ) из `/opt/mgimo/models`. Калибровка на живых примерах: метка `dangerous` шумная (0.75–0.9 на обычных жалобах), поэтому эскалирует только при ≥ 0.95 без признаков брани; осмысленность дополнена проверкой редких биграмм.
- **Этап 2:** GigaChat-2 Lite, `response_format: json_schema` со `schema` на верхнем уровне (вложенный `json_schema.schema` API отвергает); запасной путь — принудительный вызов функции. Пост-фактум: студент вызов не ждёт. Оскорбление/риск → ручная модерация; 3 сбоя → ручная модерация; ИИ не закрывает обращения.
- **Данные:** буфер AES-256-GCM с ключом дня (ключи вне БД, уничтожаются через 15 дней), удаление в транзакции принятия; реестр — свой DEK на обращение; `author_ref` = HMAC; `complaint_authors` только для именных и конфиденциальных; IP не пишется (фильтр access-лога).
- **Роли:** исполнитель (staff.deanery) и куратор (admin.demo); субъект жалобы получает 404.
- **Тесты:** 16, включая канарейку `КАНАРЕЙКА-7f3a` по всем таблицам и логам; тест нашёл утечку текста в поле формы буфера — исправлено.
- **Срезано:** кластеры (коллективные обращения) и вложения — как разрешает спецификация.
- **Инфраструктура:** ключ GigaChat — в `/opt/mgimo/app.env` (640), связка сертификатов НУЦ Минцифры — `/opt/mgimo/certs/russian-trusted-ca.pem`, только для вызовов GigaChat.
