# Команда и правила работы

| Код | Роль в диздоке | Имя | Зона ответственности |
|---|---|---|---|
| A | Backend / инфраструктура / безопасность / ИИ | _заполнить_ | API, Postgres, GigaChat, тесты, deploy |
| B | Frontend / UX / дизайн | _заполнить_ | React, экраны, навигация, мобильная версия |

**Как обновлять:** замените `_заполнить_` на реальные имена. В задачах `#role/a` и `#role/b` уже назначены направления работ.

## Ежедневный ритуал (10 минут)

1. Откройте [[00 — ДАШБОРД]] и список просроченных задач.
2. Через Tasks Kanban перетащите максимум 1–3 задачи на человека в «In progress».
3. Сверьте зависимости в [[02 — Дорожная карта.canvas|дорожной карте]].
4. Задачи, которые нельзя продолжать, пометьте `#blocked` и запишите причину в заметку.
5. В конце дня закройте сделанное, зафиксируйте демо и один риск.

## Определение готовности (Definition of Done)

Задача завершена только когда: (1) код/материал готов; (2) результат проверен; (3) нет очевидного дефекта прав доступа; (4) при необходимости записаны тесты; (5) ответственный отметил задачу в Markdown/Kanban.

## Совместная работа

Не редактируйте один Markdown-файл одновременно из двух несинхронизированных копий. Для совместного vault используйте согласованный способ синхронизации и резервные копии. Git удобен, если оба участника уже им пользуются; Obsidian не заменяет GitHub Issues и CI.

## Где что менять

- Статус подзадачи — в Tasks Kanban, чекбоксе или напрямую в файле модуля.
- Дату — в Gantt Calendar; изменение сохраняется в Markdown.
- Большую спецификацию — в папке `Разделы/` (содержимое диздока).
- Статус модуля — верхний чекбокс в файле модуля; только после закрытия всех подзадач.
