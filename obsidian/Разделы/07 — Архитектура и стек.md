# 7. Архитектура и стек

Рекомендуемый стек: React + TypeScript на фронте, Python + FastAPI на бэкенде, одна PostgreSQL как единственное хранилище, деплой в Docker Compose на российском VPS. Выбор сделан под три условия: двое разработчиков с ИИ-ассистентами, 16 дней, доступность без VPN из России. При этом архитектура не закрывает путь к росту: API без состояния, сессии и очередь в БД, файлы за интерфейсом хранилища.

Клиент общается только с Caddy. API обращается к БД, файлам и GigaChat, а worker работает с той же БД и не принимает запросов снаружи.

#### Стек по слоям

Версии — актуальные стабильные на день старта разработки, фиксируются lock-файлами; мы не проверяли совместимость конкретных версий, это задача первого дня.

| Слой | Выбор | Почему |
| --- | --- | --- |
| Фронтенд | React + TypeScript + Vite, React Router, TanStack Query | Самый распространённый стек для ИИ-ассистентов, меньше вероятность ошибок генерации; Vite быстро собирается; SPA просто хостить статикой |
| Стили и UI | Tailwind CSS + shadcn/ui (Radix) + Lucide | Доступные примитивы из коробки, легко задать токены из раздела 6, лицензии MIT/ISC |
| Формы и валидация | react-hook-form + zod | Одна схема на клиенте; сервер всё равно валидирует заново |

| Слой | Выбор | Почему |
| --- | --- | --- |
| PWA | vite-plugin-pwa | «На экран Домой» и быстрый повторный запуск; офлайн-режим данных не делаем |
| API | Python 3.12 + FastAPI + Pydantic v2 | Стек команды уже знаком по Python и SQLAlchemy; FastAPI автоматически даёт OpenAPI-контракт; у GigaChat есть Python-SDK |
| ORM и миграции | SQLAlchemy 2.0 (async, asyncpg) + Alembic | Версионируемая схема БД, воспроизводимый деплой с нуля |
| БД | PostgreSQL 16, расширения btree_gist, pg_trgm (и pgvector по мере необходимости) | Exclusion constraint для брони, полнотекстовый поиск, одно хранилище вместо Redis + другой БД |
| Фоновые задачи | Отдельный процесс worker на APScheduler + таблица outbox | Расчёт рисков, подсказки, автоосвобождение броней, перекатка расписания; просто и без дополнительной инфраструктуры |
| Реальное время | Server-Sent Events | Односторонний поток уведомлений, проще WebSocket и проходит через обычный HTTP |
| PDF и QR | ReportLab (PDF), segno (QR) | Генерация без браузера и тяжёлых зависимостей; шрифт с кириллицей встраивается |
| Календарь | icalendar | Фид.ics для K8 |
| ИИ | GigaChat API (официальный Python-SDK) через бэкенд | Решение команды; доступен из РФ; ключ не попадает в браузер |
| Хранение файлов | Интерфейс Storage: локальный диск сейчас, S3-совместимое потом | Замена без переписывания бизнес-логики |

| Слой | Выбор | Почему |
| --- | --- | --- |
| Входной прокси и TLS | Caddy | Автоматический HTTPS, раздаёт статику фронта и проксирует /api |
| Контейнеры и CI | Docker Compose; GitHub Actions или GitVerse CI | Одна команда docker compose up поднимает всё, команда уже знакома с Docker |
| Тесты | pytest + httpx (API), Vitest (UI), Playwright (сквозные, 360 px), axe-core (доступность) | Необходимы для критерия «имплементация» |
| Логи | structlog (JSON), без персональных данных | Для отладки без утечек |

#### Связь фронта и бэка

FastAPI генерирует openapi.json; из него автоматически строятся TypeScript-типы и клиент ( openapi-typescript ). Если сервер изменил контракт, сборка фронта падает на типах — это лучшая защита от рассинхрона двух разработчиков, работающих параллельно с ИИ.

#### Структура репозитория

. ├── AGENTS.md # главный файл для ИИ-агентов (раздел 14) ├── docs/ # диздок, ADR, промпты, журнал ИИ ├── apps/ │ ├── web/ # React + Vite │ │ └── src/{app,features,components,lib,styles} │ └── api/ # FastAPI │ └── app/{core,auth,modules,jobs,ai,pdf,storage} ├── infra/ # docker-compose, Caddyfile,.env.example ├── seed/ # генератор вымышленных данных └── e2e/ # Playwright

Внутри modules — по одной папке на доменный модуль ( schedule, grades, requests, notifications, booking, reports, pass, calendar, share, assistant ). В модуле: router.py, service.py, models.py, schemas.py, policy.py. Файл policy.py — единственное место, где решается, кто может видеть и менять объект (раздел 10).

#### Почему не другие варианты

| Вариант | Плюс | Почему не берём |
| --- | --- | --- |
| Next.js как полный стек | Один язык, много примеров | SSR и режимы рендера добавляют сложность деплоя без выигрыша для закрытого кабинета; бэкенд всё равно нужен для фоновых задач |
| Supabase / Firebase | Быстрый старт | Риск доступности из РФ без VPN не проверен, данные за рубежом, меньше контроля над безопасностью |
| Vercel / Netlify / Render для деплоя | Одно нажатие | Доступность без VPN для жюри не гарантирована — это прямое требование конкурса; мы это не проверяли и не будем рисковать |
| Node.js (Fastify / NestJS) на бэке | Один язык с фронтом | Валидный вариант, если команда предпочтёт TypeScript везде; мы выбрали Python из-за знакомого стека и SDK GigaChat |
| Redis + Celery/Arq сразу | Зрелая очередь | Лишняя служба на этапе прототипа; добавляем, когда выйдем за пределы одного сервера |

#### Путь к масштабированию (требование конкурса «гибкость под разное число пользователей»)

1. Сейчас: один VPS, API в 2–4 воркерах uvicorn, одна БД. Расчётно хватает на жюри и десятки одновременных пользователей — это оценка, нагрузочный тест (k6 или locust) планируется на день 13.

2. Дальше: несколько инстансов API за балансировщиком (сессии уже в БД), PgBouncer, реплика на чтение.

3. Дальше ещё: объектное хранилище вместо диска, Redis для очереди и кэша, CDN для статики, партиционирование таблиц notifications и audit_log.
