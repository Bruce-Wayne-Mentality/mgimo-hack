# 12. Нефункциональные требования, хостинг и деплой

Цифры в таблице ниже — наши цели, а не измеренные значения. Измерить их нужно на дне 13 плана (раздел 14).

### 12.1 Нефункциональные требования

| Код | Требование | Цель | Как проверяем |
| --- | --- | --- | --- |
| NFR-01 | Мобильная вёрстка | Все сценарии работают от 360 px, без горизонтального скролла | Playwright на 360×740 |
| NFR-02 | Скорость загрузки | Главный экран интерактивен за пару секунд на обычном мобильном интернете | Lighthouse (мобильный профиль) |
| NFR-03 | Быстрый отклик API | Обычные запросы чтения отвечают быстро при нагрузке жюри и опубликованных тестовых аккаунтов | k6 или locust на дне 13 |
| NFR-04 | Доступность | Все экраны управляются с клавиатуры, контраст не ниже WCAG AA, цвет не единственный носитель смысла (светофор дублируется иконкой и текстом) | axe-core в Playwright |

| Код | Требование | Цель | Как проверяем |
| --- | --- | --- | --- |
| NFR-05 | Доступность сервиса | Сайт открывается из России без VPN и работает до 28 ноября | Российский хостинг, проверка с российского мобильного интернета, внешний мониторинг |
| NFR-06 | Восстановление | База и демо-данные поднимаются одной командой за минуты | make reset-demo, тест на чистом сервере |
| NFR-07 | Демо-данные сбрасываются | Жюри может создавать заявки и брони, ночью сид возвращает чистое состояние | Задача worker раз в сутки |
| NFR-08 | Режим ошибок | У каждого экрана есть состояния «загрузка», «пусто» и «ошибка с кнопкой повторить» | Чек-лист по инвентарю экранов из раздела 6 |
| NFR-09 | Слабая сеть | Расписание на сегодня открывается из кэша PWA, если сети нет | Ручная проверка «офлайн» в DevTools |
| NFR-10 | Тестовые аккаунты | Минимум два студента с разными данными и аккаунт сотрудника | Смоук-тест на боевом адресе |

### 12.2 Хостинг

Рекомендация: одна небольшая виртуальная машина (VPS) у российского провайдера, Docker Compose, домен в зоне.ru или поддомен провайдера, сертификат от Let's Encrypt через Caddy. Для конкурсной нагрузки (жюри и пара десятков студентов) хватит скромной конфигурации, но это оценка, а не измерение: размер уточнится на нагрузочном тесте.

| Вариант | Плюсы | Минусы | Вердикт |
| --- | --- | --- | --- |
| VPS у российского провайдера | Полный контроль, открывается из России, один docker compose up | Администрирование на нас | Выбираем |

| Вариант | Плюсы | Минусы | Вердикт |
| --- | --- | --- | --- |
| Зарубежный PaaS (Vercel, Render, Fly.io и тому подобные) | Деплой в один клик | Доступность из России без VPN я не проверял, риск провалить один из обязательных пунктов | Не берём |
| Бесплатный тариф со спящим контейнером | Дёшево | Холодный старт при первом входе жюри портит впечатление | Не берём |

Разработчику нужно самому выбрать провайдера и тариф и сверить цену: я не проверял актуальные цены по конкретным провайдерам.

### 12.3 Контейнеры

```yaml
# docker-compose.yml (выдержка)
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD_FILE: /run/secrets/db_password
    volumes: [ "pgdata:/var/lib/postgresql/data" ]
    healthcheck: { test: ["CMD-SHELL", "pg_isready -U postgres"], interval:
5s }
api:
    build: ./backend
    env_file: .env            # секреты только здесь, файл не в git
    depends_on: { db: { condition: service_healthy } }
    volumes: [ "files:/data/files" ]
  worker:
    build: ./backend
    command: python -m app.worker
    env_file: .env
    depends_on: { db: { condition: service_healthy } }
  web:
    image: caddy:2
    ports: [ "80:80", "443:443" ]
    volumes: [ "./Caddyfile:/etc/caddy/Caddyfile",
"./frontend/dist:/srv/web", "caddy:/data" ]
    depends_on: [ api ]
volumes: { pgdata: {}, files: {}, caddy: {} }
```

### 12.4 Переменные окружения

| Переменная | Назначение | Где хранится |
| --- | --- | --- |
| DATABASE_URL | Подключение к БД | .env на сервере |
| SESSION_SECRET | Подпись CSRF-токенов | .env на сервере |
| DOC_SIGN_KEY | HMAC-ключ подписи документов | .env на сервере |
| GIGACHAT_CREDENTIALS | Ключ GigaChat API | .env на сервере |
| APP_ENV | dev или prod (в prod включаются Secure -куки и строгий CORS) | .env |
| DEMO_MODE | Показывать тестовые логины на странице входа и ночной сброс | .env |

В репозитории лежит только.env.example с пустыми значениями.

### 12.5 Деплой и эксплуатация

1. git pull на сервере, docker compose build, docker compose run --rm api alembic upgrade head, docker compose up -d.

2. Фронт собирается локально или в CI и кладётся в frontend/dist; на сервере Node не нужен.

3. make seed заливает демо-данные; make reset-demo сбрасывает их без потери схемы.

4. Проверка живости: GET /health дёргает внешний монитор каждые 5 минут до 28 ноября; при падении — уведомление команде.

5. Откат: предыдущий образ по тегу и alembic downgrade -1. Если миграция деструктивная, перед деплоем делается pg_dump.

6. Окружения два: dev (локально, docker compose -f compose.dev.yml ) и prod (сервер). Стейджинга нет: для двух разработчиков и 16 дней это лишнее.
