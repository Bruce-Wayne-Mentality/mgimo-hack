# 13. Демо-данные и тестовые аккаунты

Все данные выдуманы. ФИО собираются скриптом из списков имён и фамилий с случайным сочетанием, номера зачёток — с префиксом DEMO-, чтобы не спутать с реальными. Расписание строится автоматически относительно текущей недели, поэтому демо выглядит актуально при любой дате проверки. Реальных преподавателей и студентов в данных нет, но мы можем брать открытые данные расписания как образец структуры, если команда решит его распарсить: конкурс это разрешает, но имена преподавателей в таком случае заменяются на выдуманные.

### 13.1 Тестовые аккаунты для жюри

Логины и пароли ниже — предложение; команда может заменить их. Пароли должны быть такими, чтобы жюри могло ввести их с телефона, и при этом проходить проверку длины. Хэши генерирует сид-скрипт, в коде лежат только хэши.

| Роль | Логин | Пароль | Профиль |
| --- | --- | --- | --- |
| Студент А | student.anna | Demo-Anna-2026 | 2 курс, хорошая успеваемость, зелёный светофор, есть готовая справка и одна заявка «в работе» |
| Студент Б | student.boris | Demo-Boris-2026 | 3 курс, жёлтый светофор по одной дисциплине, пропущенные занятия, заявка в статусе «нужны уточнения» |
| Студент В | student.vera | Demo-Vera-2026 | 1 курс, красный светофор, пустые список заявок и броней для показа пустых состояний |
| Сотрудник | staff.deanery | Demo-Staff-2026 | Деканат одного факультета, очередь из заявок студентов А, Б и В |
| Админ | admin.demo | Demo-Admin-2026 | Журнал действий |

Конкурс требует минимум два студента с разными данными; третий (В) нужен для демонстрации пустых состояний и красного светофора, это наше решение, не требование регламента. Аккаунт админа необязателен: если времени не хватает, его можно убрать без потерь.

### 13.2 Объём сида

| Сущность | Количество |
| --- | --- |
| Факультеты | 2 (чтобы проверить права «своего факультета») |
| Группы | 4 |
| Студенты | 3 тестовых + 40 фоновых (для нагрузочного теста и панели сотрудника) |
| Дисциплины | по 6 на группу |
| Занятия | 4 недели вперёд и назад от текущей даты, с 3–5 изменениями (перенос, отмена, замена аудитории) |
| Контрольные точки | 4–6 на дисциплину, часть с ближайшими дедлайнами |
| Типы заявок | 6 из каталога раздела 4 |
| Заявки | 8 в разных статусах, чтобы все статусы были видны на экране |
| Аудитории и переговорные | 8 |
| Уведомления | 5–8 на студента, разных типов |

### 13.3 Данные, которые должны быть в сиде обязательно

Это данные, без которых демо жюри не покажет ключевые моменты:

1. У студента А в расписании на сегодня есть одно перенесённое занятие с пометкой «было → стало» и одно занятие в ближайшие два часа.

2. У студента Б дедлайн в ближайшие три дня и расчёт, что для зачёта нужно добрать баллов (для «что если» и жёлтого светофора).

3. У каждого студента есть хотя бы одно уведомление от деканата, для студента А — с дедлайном.

4. Ровно одна бронь в будущем у студента А и свободные слоты у других аудиторий; есть аудитория, где бронь занята бронью студента Б (для демо конфликта).

5. В очереди сотрудника есть просроченная по сроку заявка, чтобы показать подсветку SLA.

6. Одно анонимное обращение «красной кнопки» с известным кодом отслеживания на странице входа демо (код — выдуманный, для показа).

### 13.4 Тексты в сиде

Все тексты — объявления, ответы деканата, документы-правила — пишет ИИ по заданию от разработчика, и промпт сохраняется в docs/ai/prompts/ для описания процесса. В документах-правилах не нужно упоминать реальный вуз как источник правил: это конкурсный вымысел, и тексты не должны выдаваться за официальные.
